# GraphPlotter — Лабораторные работы 1–2

Приложение на C# / Windows Forms (.NET 8). Окно содержит две вкладки:

- **Лаб. 1 — Визуализация данных**: построение графика функции, заданной
  **аналитически** (формулой) или **таблично** (из текстового файла).
- **Лаб. 2 — Нелинейные уравнения**: уточнение корня уравнения f(x)=0
  **методом парабол** с заданной точностью ε, с локализацией корня по
  графику (тем же компонентом, что и в лаб. 1).

Обе вкладки построены на одном и том же переиспользуемом компоненте
`GraphControl` (сетка, оси, масштабирование, панорамирование) — то есть
лаб. 2 в буквальном смысле использует приложение из лаб. 1 для локализации
корня, как и требуется по заданию.

## Как собрать и запустить

Нужен установленный .NET SDK 8.0 (или новее): https://dotnet.microsoft.com/download

```bash
cd GraphPlotter
dotnet run
```

Либо откройте `GraphPlotter.csproj` в Visual Studio 2022+ и запустите (F5).
Приложение — обычный WinForms-проект, работает только под Windows.

## Возможности и соответствие требованиям задания

- **Графический интерфейс.** Переключатели вверху окна позволяют выбрать
  форму задания функции: «Аналитическая функция» или «Табличная функция».
- **Начало координат по умолчанию — в центре области построения.**
  При запуске и после каждого нового построения (`ResetView`) центр экрана
  соответствует точке (0, 0); оси Ox (горизонтальная, независимая переменная)
  и Oy (вертикальная, зависимая переменная) рисуются со стрелками, делениями
  и подписанными значениями.
- **Масштабирование.** Колесо мыши увеличивает/уменьшает масштаб относительно
  точки под курсором. Шаг сетки и число знаков после запятой в подписях осей
  пересчитываются динамически («красивые» шаги 1/2/5·10ⁿ), поэтому при
  сильном увеличении значения корректно отображаются вплоть до разряда
  десятитысячных (0.0001) и мельче — ограничения на глубину масштабирования
  практически нет.
- **Смещение центра координат.** Перетаскивание левой кнопкой мыши по полю
  графика панорамирует вид. Кнопка «Сбросить вид» возвращает исходное
  положение и масштаб.
- **Аналитическая функция.** Поле ввода принимает выражения в стандартной
  математической записи: `+ - * / ^`, скобки, неявное умножение (`2x`,
  `3(x+1)`), элементарные функции `sin, cos, tg/tan, ctg/cot, arcsin, arccos,
  arctg/arctan, sqrt, ln, lg (log10), exp, abs` и константы `pi`, `e`.
  Пример: `sin(x) + 0.5*cos(2*x)`, `x^2 - 3*x + 2`, `1/x`, `sqrt(4 - x^2)`.
  Разрывы функции (деление на 0, область определения) отображаются как
  разрывы линии графика, а не как ошибка.
- **Табличная функция.** Кнопка «Загрузить файл...» открывает диалог выбора
  текстового файла. Файл — два столбца чисел (x и y), разделённых **любым**
  стандартным разделителем: пробелом, табуляцией, точкой с запятой (можно и
  их комбинацией/повторением). Количество строк произвольно. Десятичным
  разделителем может быть как точка, так и запятая. Пустые строки и строки,
  начинающиеся с `#` или `//`, пропускаются. После загрузки график
  автоматически масштабируется так, чтобы все точки поместились в область
  просмотра; данные соединяются линией и отмечаются точками.
  Пример файла — `sample_data.txt` в этой папке.

## Лаб. 2 — метод парабол

Численная схема реализована в `ParabolaMethodSolver.cs`, не зависит от UI
и может быть протестирована отдельно. Алгоритм:

1. Пользователь по графику (масштабируя/панорамируя, как в лаб. 1) визуально
   находит отрезок `[a, b]`, на концах которого функция меняет знак —
   это и есть **локализация корня**.
2. На каждой итерации через три точки `x0`, `x1 = (x0+x2)/2`, `x2` строится
   интерполяционный многочлен 2-й степени (парабола) по формуле Ньютона
   с разделёнными разностями.
3. Находится корень этой параболы, лежащий внутри `[x0, x2]` (если
   коэффициент при x² вырожден или дискриминант отрицателен — используется
   формула секущей как откат).
4. По знаку функции в найденной точке отрезок сужается (аналогично методу
   половинного деления, но со сверхлинейной скоростью сходимости).
5. Процесс останавливается, когда `|f(x_new)| < ε` или ширина отрезка `< ε`
   (по умолчанию `ε = 10⁻⁴`, для варианта задания `x² − 3 − 2cos(2πx)`).

На вкладке лаб. 2 выводятся: таблица итерационной последовательности
(`x0, x1, x2, x_new, f(x_new)`, ширина отрезка), итоговый корень, значение
функции в нём, число итераций, а на графике корень отмечается точкой.
Кнопка «Показать точность» центрирует и увеличивает график вблизи корня
настолько, чтобы окрестность радиуса ε была хорошо видна — это и есть
«масштабирование до визуализации точности» из задания.

## Лаб. 3 — экстремум методом парабол

Численная схема — в `ExtremumMethodSolver.cs` (метод последовательной
параболической интерполяции, он же «метод парабол» для поиска экстремума;
отдельная от лаб. 2 реализация, своя численная схема). Алгоритм:

1. По графику визуально подбирается отрезок `[a, b]` **унимодальности** —
   значение функции в середине отрезка не хуже значений на его концах
   (для минимума — меньше, для максимума — больше; поиск максимума
   реализован сведением к поиску минимума `g(x) = -f(x)`).
2. На каждой итерации через `x0 < x1 < x2` проводится парабола, по явной
   формуле находится абсцисса её вершины — новое приближение `x_new`.
3. Из четырёх точек `{x0, x1, x2, x_new}` формируется новая тройка,
   сохраняющая унимодальность и содержащая точку с наилучшим значением.
4. Остановка — когда `|x_new − x1| < ε` или ширина отрезка `< ε`.
5. В найденной точке численно (центральными разностями) считаются первая
   и вторая производные исходной `f(x)` — не библиотечным дифференцированием,
   а по формулам `f'(x)≈(f(x+h)-f(x-h))/(2h)`, `f''(x)≈(f(x+h)-2f(x)+f(x-h))/h²`.

На вкладке лаб. 3: переключатель «Минимум / Максимум», поля `a, b, ε`,
таблица итераций, и итог — `x*, f(x*), f'(x*), f''(x*)`, тип экстремума,
число итераций; найденная точка отмечается на графике, кнопка «Показать
точность» увеличивает вид до масштаба ε.

## Лаб. 4 — определитель методом Гаусса (вариант 1)

Реализовано в `GaussianDeterminantSolver.cs`. Матрица `A` (4×4) из задания
вводится через таблицу на вкладке «Лаб. 4» (значения по умолчанию уже
заполнены; столбец `b` показан только для справки — это та же СЛАУ из
задания, но для определителя он не нужен и в расчёте не участвует).

Алгоритм — метод Гаусса **с постолбцовым (частичным) выбором главного
элемента**: на шаге k среди строк k..n-1 в столбце k ищется максимальный
по модулю элемент, его строка переставляется на место k (со сменой знака
определителя), затем обычное исключение Гаусса приводит матрицу к
верхнетреугольному виду. `det(A) = (±1)^(число перестановок) × произведение
диагональных элементов`. Специального вида матрицы (симметричность,
трёхдиагональность и т.п.) этот метод не требует, поэтому предварительного
преобразования матрицы не делается.

Как и требует задание, для проверки используется **независимый способ** —
разложение определителя по алгебраическим дополнениям (миноры по первой
строке, `DeterminantCofactor` в том же файле); оба значения и их
расхождение выводятся в текстовом логе вместе с пошаговым ходом метода
Гаусса (выбор ведущего элемента на каждом шаге и матрица после исключения).

## Лаб. 5 — метод релаксаций (та же СЛАУ, что в лаб. 4)

Реализовано в `RelaxationMethodSolver.cs`. Метод релаксаций (SOR —
Successive Over-Relaxation) на каждой итерации пересчитывает компоненты
решения по формуле

```
x_i := (1-ω)·x_i + ω/a_ii·(b_i − Σ_{j<i} a_ij·x_j^new − Σ_{j>i} a_ij·x_j^old)
```

то есть уже обновлённые в текущей итерации компоненты используются сразу
(как в методе Зейделя), а параметр `ω` (по умолчанию `1.0`, что в точности
даёт метод Зейделя) можно менять в интерфейсе в пределах `(0, 2)`.
Начальное приближение — нулевой вектор. Точность оценивается по
**максимальной по модулю разнице компонент** решения между соседними
итерациями (как и требует задание), критерий остановки — эта величина
`< ε`.

На вкладке «Лаб. 5» — та же таблица `A | b`, что и в лаб. 4 (оба столбца
теперь редактируемые, так как решается именно `Ax = b`), поля `ω` и `ε`,
таблица итерационной последовательности и итог: столбец-вектор решения
`x` и невязка `r = A·x − b` (построчно и как `max|r_i|`), число итераций.

## Лаб. 6 — аппроксимация функции (f(x) = x²−3−2cos(2πx), как в лаб. 2–3)

Три части задания — три вложенные вкладки внутри «Лаб. 6»:

**6.1 Интерполяция многочленом.** `PolynomialInterpolation.cs` — многочлен в
**барицентрической форме Лагранжа** (та же единственная функция, что и
классический Лагранж, но вычисляется гораздо устойчивее — это важно, так
как задание требует степеней от 1 до 50). Число узлов = степень + 1,
узлы равномерно расставлены на `[a,b]`. На графике: f(x) — синим,
многочлен — оранжевым, узлы — зелёными точками, значение в произвольной
точке x0 — звёздочкой. При высоких степенях на равномерной сетке заметно
явление Рунге (сильные колебания около краёв отрезка) — это ожидаемый
результат, а не ошибка.

**6.2 Кусочно-линейная интерполяция.** `PiecewiseLinearInterpolation.cs` —
для каждого отрезка `[x_i,x_{i+1}]` хранятся коэффициенты прямой
`y=k·x+b`; поиск нужного отрезка — бинарным поиском, поэтому число точек
может быть большим (до 200000 в интерфейсе). Есть просмотр уравнения
выбранного отрезка и кнопка, приближающая график к этому отрезку.
Цвета — как в 6.1; значение в x0 тоже отмечается звёздочкой.

**6.3 Наилучшее среднеквадратичное приближение (вариант 5).**
`LeastSquaresApproximation.cs` — полиномы 4-й и 5-й степени (через
нормальные уравнения МНК, решаемые методом Гаусса из `LinearAlgebraUtils.cs`),
показательная `y=a·e^(bx)` и логарифмическая `y=a·ln(x)+b` модели (обе —
через линеаризацию и ту же полиномиальную МНК-подпрограмму со степенью 1).
Отрезок `[a,b]` по умолчанию `[2.5, 5]` — строго положительный, что нужно
для показательной/логарифмической моделей (и там, где f(x) на этом
отрезке тоже положительна). В каждую точку вносится случайная
относительная погрешность 30–300% со случайным знаком. Для каждого
варианта выводятся коэффициенты, сумма квадратов ошибок (SSE) и RMSE;
лучший вариант выбирается по минимальной SSE, с кратким выводом. На
графике — f(x) (серым), зашумлённые точки (чёрным) и все 4 кривые
приближения разными цветами.

`PolynomialInterpolation`, `PiecewiseLinearInterpolation`,
`LeastSquaresApproximation`, `LinearAlgebraUtils`) написаны с нуля и не
используют сторонних библиотек/пакетов численных методов — только базовые
арифметические операции и элементарные функции `Math.*` там, где это
нужно для вычисления самой `f(x)`, как и было оговорено.

## Дальнейшее развитие

`GraphControl` спроектирован для переиспользования в следующих лабораторных
работах без изменений — достаточно передавать функцию/данные через свойства
`Function`, `TablePoints`, `MarkerPoint`.
